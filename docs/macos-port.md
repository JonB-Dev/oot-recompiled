- **Apple Silicon / Metal experiment**
- The experiment has been based on [JonB-Dev's OoT: Recompiled 0.6.1](https://github.com/JonB-Dev/oot-recompiled/commit/e5c6eddc0aa35476a027ddb6cc7ac149ee22b6fb), with AI assistance. Original authorship, credits, and GPL-3.0 licensing have been retained.
- macOS build support, Metal raster rendering, converted ray pipelines, resource lifetime/readback fixes, and original-rate presentation have been added. The original 58 renderer patches are followed by `rt64-patches/macos/0001-apple-silicon-metal.patch` only in the macOS preparation script; the Windows patch series has been preserved.

- **GUI build:** `Build macOS App.command` opens the native local builder described in the README. ROM validation, dependency checks, cancellation, and duplicate-build protection wrap the same scripts below. ZIP downloads are supported through an isolated branch checkout.

- **Reproduction**
- Full Xcode with its Metal Toolchain, Homebrew CMake/Ninja/LLVM/lld/Make/Git/SDL2/FreeType, and Python 3.10+ are required. An available Conda interpreter can be selected with `export PYTHON_BIN="$(conda info --base)/bin/python"`.
- The branch can be obtained with `git clone --recurse-submodules --branch codex/macos-experiment https://github.com/boscacci/oot-recompiled.git`, followed by `cd oot-recompiled`.
- A personally supplied, unmodified NTSC-U 1.0 ROM is required. Its SHA-1 must be `ad69c91157f6705e8ab06c79fe08aad47bb57ba7`. Its location is supplied through `export ROM="/path/to/USA-1.0.z64"`; ROM bytes and generated game code are excluded from Git.
- The raster app is built with `tools/build_macos.sh "$ROM"`. The pinned decompilation, Python packages, recompiler, MIPS patches, renderer, tests, and app are prepared by that script. All registered native tests are built before CTest is run.
- For tracing, Apple's Metal Shader Converter 4.0 beta 3 (reported tool version 4.0.3) must be obtained separately under Apple's license. After that license has been reviewed and accepted, the pinned package can be prepared with `tools/setup_metal_shader_converter.sh --accept-license "$CONVERTER_PKG"`. The package is signature- and checksum-checked; it is not redistributed.
- Converted ray libraries and the tracing app are built and verified with `tools/build_macos_rt_probe.sh`. The tracing app enables Metal tracing on normal launch; `OOT_METAL_RAYTRACING=0` remains a diagnostic opt-out. Converter output is targeted at Apple GPU family 9 or later; compatibility beyond the tested M5 has not been established.
- For an isolated smoke profile, an existing opening save is required in the normal app's save directory. A disposable copy is prepared with `"$PYTHON_BIN" -m tools.init_macos_play --native-rt`; the original save is not modified. If no opening save exists, one must first be created in the raster app. The patcher is intended only for an opening save.
- A guarded level-2 run can then be performed with `"$PYTHON_BIN" tools/smoke_macos_gameplay.py "$ROM" --data-root data/native-rt-profile --enter-save --entrance 0x266 --raytracing --rt-level 2 --seconds 110 --max-rss-mib 1536 --probe build/experiment-probe.txt`. Original-rate output and two AO rays are selected by that profile; textures are disabled. RSS and driver faults are monitored, and the process is stopped at the deadline.
- An equivalent tracing-off check can be performed by replacing `--raytracing --rt-level 2` with `--raster-rt-app`. Shader diagnostics can be enabled with `--shader-validation`. Optional frame recording can be requested with `--capture-gameplay --capture-seconds 1 --record-start-tick 1200 --dismiss-tutorial`; an unlocked desktop and FFmpeg are required. Raw sessions remain ignored; curated gameplay illustrations are kept under `docs/screenshots/` for the README.
- Native regressions are run by both build scripts. Python checks are run with `"$PYTHON_BIN" -m unittest discover -s tests -p 'test_macos_*.py'`, then the same command with `-p 'test_prepare_*.py'` and `-p test_metal_rt_root_signature.py`. Shader conversion and GPU filter/readback tests are included in CTest.
- Logs, timing probes, and captures are written under ignored `build/`, `data/`, or `outputs/`. Process RSS does not include every GPU allocation and must not be treated as total unified-memory usage.

- **Recorded observations and limits**
- The original runs were recorded on an Apple M5. At [source commit `054d24d`](https://github.com/boscacci/Zelda64Recomp-OoT/commit/054d24d91ae5fde14b09a6ce0c942630d0680c74), a 110-second run was completed at tracing level 2, two AO rays, no replacement textures, a 3024×1898 drawable, and a 3060×1920 internal render size. A median presentation interval of 50.024 ms and 20 presents/second were observed in seconds 69–92. Peak process RSS was 567.0 MiB; no driver fault was detected in that run.
- Full-detail OoT Reloaded v11 RT64 textures were subsequently compared at different AO and antialiasing settings on the squashed code. Fresh measurements, capture provenance, and the bounded scene-tour results are recorded in [the benchmark data](benchmarks/2026-11-09-m5.json) and summarized in the README. Earlier Half/Quarter trials were not reused for that comparison. Packs are not supplied.
- Fresh verification of the squashed source is recorded separately by commit, hardware, settings, duration, and result. Historical measurements above must not be attributed to a newer commit without another run.
- Long sessions, broad scene transitions, level-3 lighting, localized flicker, controller-specific behavior, and other Macs remain insufficiently tested. GPU faults, black output, and instrumented CPU crashes were observed during earlier experiments; short passing runs do not establish sustained stability. The 60 fps path remains problematic, and Windows has not been retested.
- High-level video capture, installer integration, and automatic updates have not been implemented on macOS; the frame recorder used by the probes is separate. The experiment is shared as source, without a release or upstream support obligation.
